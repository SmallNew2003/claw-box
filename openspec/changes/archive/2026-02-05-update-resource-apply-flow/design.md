# 设计说明：资源申请 Tabs + 多条配置

## 1. 页面结构
- 顶部为“基本信息”固定区域（必填）。
- 下方为 Tabs：`模型申请`、`知识库申请`、`智能体配置`。
- 模型/知识库 Tab 内为“申请条目列表”。每条目可删除，支持“新增一条”。
- 智能体 Tab 为“智能体条目列表”。每条目包含基本信息与绑定区，支持新增/删除。

## 2. 条目模型
- 模型条目：`sourceType(new|existing)` + `existingModelId?` + 新申请字段（QPS/TPM/平均 tokens/用户规模/算力描述等）。
- 知识库条目：`sourceType(new|existing)` + `existingKnowledgeId?` + 新申请字段（类型/向量库/数据量/来源等）。
- 智能体条目：基本信息 + `bindModels[]`（必选） + `bindKnowledges[]`（可选）。

## 3. 绑定规则
- 智能体绑定的模型/知识库选项来源于当前申请单内已添加的模型/知识库条目。
- 若删除模型/知识库条目，应同步移除智能体绑定或提示绑定失效。
- “关联已有”资源仅记录绑定关系与资源摘要，不走审批（demo 直接视为已通过）。

## 4. 提交与校验
- 必填：基本信息。
- 业务校验：模型/知识库/智能体至少其一有条目。
- 智能体条目必须绑定至少一个模型。
- 当 `sourceType === 'existing'` 时，仅提交资源 ID 与展示字段；当 `sourceType === 'new'` 时提交完整配置字段。

## 5. 示例映射
示例：智能体A（新增模型A，已有知识库A、新增知识库B）、智能体B（已有模型B、已有知识库A、新增知识库B）。
- 模型条目：ModelA(new)、ModelB(existing)
- 知识库条目：KB-A(existing)、KB-B(new)
- 智能体A绑定：ModelA + KB-A/KB-B
- 智能体B绑定：ModelB + KB-A/KB-B
