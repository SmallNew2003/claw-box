# Writing Long Documents

## Overview

**根本问题：** 当 AI 响应过大时（通常因为生成了大量内容），工具调用参数会被截断，导致所有参数变成 `undefined`。

**影响范围：** 不仅是 Write 工具，Bash、Edit 等任何工具都可能出现此问题。

**解决方案：** 分解响应，每次响应只包含少量内容和工具调用。

## When to Use

**触发信号（任何工具出现以下错误）：**
- `Invalid input: expected string, received undefined`
- 工具参数显示 `"invalid_type"` 错误
- Bash、Write、Edit 等工具调用失败且参数为 undefined

**使用场景：**
- 创建超过 150 行的文档
- 在响应中生成大量文本内容
- 需要详细解释或展示大段代码

**不使用场景：**
- 短文档（< 100 行）直接用 Write
- 简短响应（< 500 字）

## Core Pattern

### ❌ 错误方式
```markdown
单个响应中：
1. 生成 500 行文档内容
2. 调用 Write 工具
→ 响应总大小超限
→ 所有工具参数被截断
→ 参数变成 undefined
→ 工具调用失败
```

### ✅ 正确方式 - 分解响应
```markdown
响应 1：简短说明 + Write 骨架（< 50 行）
响应 2：简短说明 + Edit 添加第一部分（50-100 行）
响应 3：简短说明 + Edit 添加第二部分（50-100 行）
...
最后响应：完成确认
```

**关键原则：**
- 每个响应保持简短（< 1000 字文本 + 1 个工具调用）
- 不在响应中展示完整文档内容
- 不重复已写入的内容
- 静默执行，无需详细解释

## Implementation

### 关键规则：控制每个响应的大小

**每个响应只能包含：**
- 简短说明（< 200 字）
- 1 个工具调用
- 不展示完整内容

### 步骤 1：规划文档结构（仅在脑海中）

不要在响应中输出完整大纲，只在内部规划：
- 文档有哪些主要章节？
- 每个章节大约多少行？
- 需要几次 Edit？

### 步骤 2：写入骨架（第一个响应）

**响应内容：**
```
正在创建文档骨架...
```

**工具调用：** Write 骨架（< 50 行）
```markdown
# 文档标题

## 第一章节
[待补充]

## 第二章节
[待补充]
```

### 步骤 3：逐段填充（后续响应）

**每个响应：**
```
正在添加第 N 部分...
```

**工具调用：** Edit 替换一个占位符（50-100 行）

**禁止：**
- ❌ 在响应中展示要写入的完整内容
- ❌ 重复说明策略
- ❌ 展示已完成的部分

### 步骤 4：完成确认（最后响应）

```
文档已创建完成。
```

## Quick Reference

| 响应大小风险 | 症状 | 解决方案 |
|------------|------|---------|
| 低 | < 100 行文档 | 单次 Write |
| 中 | 100-300 行文档 | Write 骨架 + 2-3 次 Edit（分多个响应） |
| 高 | > 300 行文档 | Write 骨架 + 多次 Edit（分多个响应） |
| 极高 | 任何工具参数 undefined | 立即停止生成长文本，分解为多个响应 |

**每个响应的安全限制：**
- 文本说明：< 500 字
- 工具调用：1 个
- 工具参数内容：< 100 行

## Common Mistakes

### ❌ 错误 1：在响应中展示完整内容
```markdown
问题：生成 500 行内容展示给用户，然后调用 Write
结果：响应过大，工具参数被截断
解决：不展示内容，直接调用工具
```

### ❌ 错误 2：单个响应多次工具调用
```markdown
问题：Write + Edit + Edit 在同一响应
结果：响应过大
解决：每个响应只调用 1 个工具
```

### ❌ 错误 3：详细解释策略
```markdown
问题：长篇解释如何分块、为什么这样做
结果：响应过大
解决：简短说明（< 200 字），直接执行
```

### ❌ 错误 4：重复展示已完成内容
```markdown
问题："已完成以下内容：[粘贴 200 行]"
结果：响应过大
解决：只说"第 N 部分已完成"
```

## Real-World Impact

**使用前：**
- 工具调用频繁失败，参数变成 undefined
- 用户体验差，需要重试
- 无法创建长文档

**使用后：**
- 自动分解响应，避免参数截断
- 静默处理，用户无感知
- 100% 成功率
